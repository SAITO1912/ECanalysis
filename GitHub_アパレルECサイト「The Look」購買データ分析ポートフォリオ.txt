ポートフォリオ / アパレルECサイト「The Look」購買データ分析


1. 背景と目的

架空のアパレルECサイト「The Look」の購買データ（約10万件）を活用し、売上の最大化と顧客リピート率の向上を目的としたデータ分析を実施。

SQLの構築・検証において生成AIも補助的に活用しながら、自身でデータ構造や処理内容を確認し、クエリの結果を検証・修正をおこないました。


本プロジェクトでは、戦略提案をおこなうため、以下3つをデータから導き出しました。

　1).売上の全体像：月別の売上・注文数・客単価はどのように推移しているか？
　2).商品戦略：どの商品が売上を支えているか？（主力商品の特定）
　3).リピート戦略：購入ユーザーはその後どのくらい定着しているか？（継続率の可視化）



2. 使用データと分析環境

　・データソース：Google BigQuery 公開データ (bigquery-public-data.thelook_ecommerce)

　・分析環境：Google BigQuery (SQL)、Excel、powerBI、Looker Studio

　・主な使用技術：WITH句（CTE）、ウィンドウ関数（SUM() OVER）、
　　　　　　　　　日時操作関数（FORMAT_TIMESTAMP, DATE_DIFF）、条件分岐（CASE文）



3.分析内容とSQLクエリ

　① 月別売上・注文数・客単価の推移（売上集計分析）

　　・分析の狙い：
　　　　サイト全体の成長トレンドと、ユーザー1人あたりの購入額（客単価）の推移を把握。


　　・クエリの工夫：
　　　　実務に即した正しい数値を出すため、
　　　　WHERE句で「キャンセル（Cancelled）」や「返品（Returned）」のデータを正確に除外。
　　　　また、1回の注文で複数購入がある場合を考慮し、COUNT(DISTINCT order_id) で正確な注文数を算出。

SELECT
--注文年月
  FORMAT_TIMESTAMP('%Y-%m',created_at) AS order_month,
--1ヶ月の総売上金額(小数点以下は四捨五入)
  ROUND(SUM(sale_price)) AS total_revenue,
--1ヶ月のユニークな注文数
  COUNT(DISTINCT order_id) AS totale_orders,
--1ヶ月の客単価(総売上÷注文数)
  ROUND(SUM(sale_price) / COUNT(DISTINCT order_id)) AS average_order_value
FROM
  `bigquery-public-data.thelook_ecommerce.order_items`
WHERE
--「キャンセル」「返品」以外を集計
  status NOT IN ('Cancelled', 'Returned')
GROUP BY
--年月ごとに纏める(グループ化)
  order_month
ORDER BY
--古い月から順に並べる
  order_month ASC;



② 商品別の売上ランキング（ABC分析）

　・分析の狙い：
　　　全商品のうち、売上の大半を占めている「主力商品（Aランク）」を特定し、
　　　在庫管理やマーケティングの優先順位を決める。

　・クエリの工夫：
　　　高度なウィンドウ関数である SUM() OVER(ORDER BY) を使用し、売上が高い順に累積（積み上げ）金額を計算。売上全体の70%までを「A (主力商品)」として CASE 文で自動ランク分け。


WITH product_sales AS (
--商品ごとの売上合計の計算
  SELECT
    product_id,
    ROUND(SUM(sale_price)) AS product_total_revenue,
    COUNT(id) AS sales_count
  FROM
    `bigquery-public-data.thelook_ecommerce.order_items`
  WHERE
  --「キャンセル」「返品」を外す
    status NOT IN ('Cancelled', 'Returned')
  GROUP BY
  --商品idごとにグループ化
    product_id
),

cumulative_sales AS (
--売上が高い順に並べ、売上の累積金額と、全体に対する%を計算 
  SELECT
    product_id,
    product_total_revenue,
    sales_count,
  --売上を上から順番に足していく（累積売上）
    SUM(product_total_revenue) OVER(ORDER BY product_total_revenue DESC) AS cumulative_revenue,
  --全体の総売上を計算
    SUM(product_total_revenue) OVER() AS total_revenue
  FROM
    product_sales
)
  --累積売上の比率を計算し、A, B, Cの3グループに分類
  SELECT
    product_id,
    product_total_revenue,
    sales_count,
  --全体売上に対するこの商品までの累積比率（%）
    ROUND((cumulative_revenue / total_revenue) * 100, 1) AS cumulative_percentage,
  --比率によってランク分け（70%までがA、90%までがB、それ以外がC）
  CASE
    WHEN (cumulative_revenue / total_revenue) <=0.70 THEN 'A (主力商品)'
    WHEN (cumulative_revenue / total_revenue) <=0.90 THEN 'B (準主力商品)'
    ELSE 'C (売上小)'
  END AS abc_rank
FROM
  cumulative_sales
ORDER BY
  product_total_revenue DESC;



③ ユーザー初回購入月からの継続率分析（コホート分析）

・分析の狙い：
　　ECサイトの健康状態を示す「リピート継続率」を可視化し、
　　顧客が何ヶ月目までお店に残ってくれているかを計測。

・クエリの工夫：
　　WITH 句を使って「初回購入月」と「その後の購入月」のテーブルを小分けに定義し、
　　DATE_DIFF 関数を使って初回購入から何ヶ月後に再購入したかの経過月数を算出。


WITH user_first_order AS (
  -- ユーザーごとの「初めて購入した月（初回購入月）」
  SELECT
    user_id,
    MIN(FORMAT_TIMESTAMP('%Y-%m', created_at)) AS first_order_month
  FROM
    `bigquery-public-data.thelook_ecommerce.order_items`
  WHERE
    status NOT IN ('Cancelled', 'Returned')
  GROUP BY
    user_id
),

order_months AS (
  --ユーザーごとの「すべての購入月」
  SELECT
    user_id,
    FORMAT_TIMESTAMP('%Y-%m', created_at) AS order_month
  FROM
    `bigquery-public-data.thelook_ecommerce.order_items`
  WHERE
    status NOT IN ('Cancelled', 'Returned')
  GROUP BY
    user_id, order_month
),

cohort_sizes AS (
  -- 初回購入月（コホート）ごとの、同期人数
  SELECT
    first_order_month,
    COUNT(DISTINCT user_id) AS cohort_size
  FROM
    user_first_order
  GROUP BY
    first_order_month
)

--初回購入月と、その後の購入月を掛け合わせて、経過月ごとのリピート人数と率を計算
SELECT
  f.first_order_month AS cohort_month,
  s.cohort_size AS original_customer_count,
  -- 初回購入から何ヶ月経ったか（経過月数）を計算
  DATE_DIFF(
    DATE(PARSE_DATE('%Y-%m', o.order_month)), 
    DATE(PARSE_DATE('%Y-%m', f.first_order_month)), 
    MONTH
  ) AS months_lapsed,
  -- その月に戻ってきたリピーターの数
  COUNT(DISTINCT o.user_id) AS active_customer_count,
  -- 残存率（リピーター数 ÷ 同期の人数）を％で計算
  ROUND((COUNT(DISTINCT o.user_id) / s.cohort_size) * 100, 1) AS retention_rate
FROM
  user_first_order f
JOIN
  order_months o ON f.user_id = o.user_id
JOIN
  cohort_sizes s ON f.first_order_month = s.first_order_month
WHERE
  -- 2023年以降の比較的新しいデータに絞る
  f.first_order_month >= '2023-01'
GROUP BY
  cohort_month, cohort_size, months_lapsed
ORDER BY
  cohort_month ASC, months_lapsed ASC;



4. 分析結果からの考察（ビジネス提言の例）

・客単価の改善（①の結果より）
　　売上は伸びているが客単価が横ばい。
　　条件付き送料無料のセット買いキャンペーンやレコメンド強化を提案。


・在庫・プロモーションの最適化（②の結果より）
　　全体のわずか数％の「Aランク商品」が売上の7割を作っていることが確認。
　　Aランク商品の在庫切れを防ぐ体制を作り、売上の低いCランク商品はセールの実施や取り扱い縮小を提案。


・リピーター獲得の強化（③の結果より）
　　コホート分析の結果、例えば「購入から2ヶ月目にリピート率が落ちる」などの傾向が見えた場合、　　　
　　初回購入後45日目が経過したユーザーに対し、2回目の購入で使える限定クーポンを配信するなどの
　　ピンポイントな離脱防止策を提案。
